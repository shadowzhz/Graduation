# Air Hockey 项目交接文档

## 1. 项目概述与当前阶段

本项目为基于计算机视觉与嵌入式硬件的空气冰壶实时目标检测、运动轨迹追踪与 AI 决策系统，主要部署于 NVIDIA Jetson 边缘计算平台，下行对接西门子 PLC 执行机构。

当前系统已全面打通从相机采集、视觉检测、动态目标追踪、相机几何去畸变、卡尔曼状态估计、统一物理轨迹预测、AI 防守决策到 PLC 控制输出的完整端到端链路：

```text
Camera (CameraManager / GStreamer appsink)
  │ (Frame: raw BGR)
  ▼
StoneDetector (HSV/Lab + 轮廓几何约束，基于 raw 坐标，支持 dynamic_roi)
  │ (CurlingState: raw pixel + confidence)
  ▼
StoneTracker (常速模型，运行于 raw 坐标，负责关联与 dynamic_roi)
  │ (Track: raw center & velocity)
  ▼
CameraGeometry (逐点去畸变 raw -> undistorted -> table；支持四点 Homography)
  │ (table 坐标)
  ▼
KalmanFilter (常量速度模型状态估计，抑制视觉抖动)
  │ (CurlingState / StoneState: table 坐标与速度)
  ▼
TrajectoryPredictor (统一物理微步模拟：摩擦阻尼、弹墙、门柱碰撞、进球判定)
  │ (PredictionState: trajectory / endpoint / duration / source_state)
  ▼
AirHockeyAI (基于预测轨迹计算拦截点与击球决策)
  │ (AIDecision: target_x, target_y)
  ▼
PlcControlAdapter (AI 目标坐标检查/限幅/时间戳)
  │ (PlcTarget；S7 DB 不接收冰壶/比分/方向/速度)
  ▼
PLCLink (周期通信/位置反馈/心跳与运动互锁) -> TO_Kinematics (S7 DB1+DB18，可选 --plc)
  └── 实际轴位置反馈 -> VisionRuntime -> AirHockeyAI
```

项目已具备视觉算法和可选 PLC 输出软件链路；本次 GStreamer-only 采集及阶段计时尚无 Jetson 实机复测数据，不代表已经完成实机曝光到控制的时延测量或联调。

### 1.1 模块依赖方向

视觉运行链的模块依赖方向如下（`VisionRuntime` 作为运行核心，编排检测、追踪、坐标几何、卡尔曼状态估计、轨迹预测、AI 决策与可选 PLC 输出）：

```text
Camera
  -> VisionRuntime
       -> Detector
       -> Tracker
       -> KalmanFilter
       -> CameraGeometry
       -> TrajectoryPredictor
       -> AirHockeyAI
       -> PlcControlAdapter (可选，仅 --plc 时启用)
```

> 视觉核心**不依赖 `冰壶仿真/` 目录**。共享物理、AI、状态契约、预测、估计、规划、控制、S7-1500T 通信及配置均在 `air_hockey/` 包内；仿真目录仅保留仿真 GUI 和配置。

## 3. 依赖环境说明

系统在开发与部署时严格区分 **普通 Python 依赖** 与 **Jetson 平台系统级依赖**。禁止引入代码未实际调用的冗余库。

### 3.1 Python 版本
* **要求**：`Python >= 3.8`
* **目标环境**：Jetson Xavier NX 生产环境运行于 `Python 3.8.10`（Ubuntu 20.04 LTS）。
* **代码兼容性规范**：核心算法与模型保持向后兼容；包含 `tuple[...]`、`类型 | None` 等注解的模块使用 `from __future__ import annotations`，避免 Python 3.8 在类或函数定义时对注解求值。Jetson 启动仍需在实际使用的 Python 3.8 中安装 NumPy、OpenCV 等依赖及系统 GStreamer 组件。

### 3.2 普通 Python 依赖（通过 pip 或系统 apt 安装）
* `numpy` (`>= 1.17.4`)：矩阵与几何变换、标定参数序列化（`.npz` 读写）。
* `opencv-python` / `python3-opencv` (`>= 4.5.0`)：图像颜色空间转换、轮廓提取、内参去畸变（`cv2.undistortPoints`、`cv2.projectPoints`）。
* `python-snap7==1.3`（可选，对接 PLC 时必需）：兼容目标 Python 3.8，通过 Snap7 原生同步 BIT 接口写控制位；版本固定是因为访问该绑定的 `_library` / `_pointer` 原生接口，其他版本会明确拒绝连接，不回退整字节写入。该绑定需要 `pkg_resources`，由系统 `python3-setuptools` 或兼容的 setuptools 提供。pip 环境安装：`python3 -m pip install "python-snap7==1.3" "setuptools<81"`；缺失依赖会显示实际导入错误。
* `tkinter`（Python 标准库 / `python3-tk`）：主界面 GUI 与仿真窗口显示。

### 3.3 Jetson / Linux 系统级依赖
* `python3-gi` (PyGObject)：提供 `gi.repository.Gst` 接口。相机仅经 GStreamer appsink 获取图像；不存在 V4L2/OpenCV 自动回退，需在目标设备确认依赖和吞吐。实际 caps 的 `framerate` 使用 `Gst.Structure.get_fraction()` 读取，避免某些 Jetson 绑定调用通用 `get_value()` 时抛出 `unknown type GstFraction`。
* `gstreamer1.0-*` 运行环境：
  * `libgstreamer1.0-0`
  * `gstreamer1.0-plugins-base`
  * `gstreamer1.0-plugins-good`
  * `gstreamer1.0-plugins-bad`
* NVIDIA Jetson 硬件多媒体编解码库：
  * `nvidia-l4t-gstreamer`：需要本应用 MJPEG 硬解码及转换元件 `nvv4l2decoder`、`nvvidconv`；预览由应用 Tk 绘制，并不启用 GStreamer 硬件显示 sink。
* `v4l-utils`：提供 `v4l2-ctl` 用于查询设备支持的硬件分辨率与格式（诊断命令，不是采集后端）。
* `libsnap7-dev` / `libsnap7.so`：若使用 S7 通信，Linux 系统层需存在 snap7 动态库。

> [!NOTE]
> 项目不依赖 PyTorch、TensorFlow、ONNX Runtime 等深度学习推理引擎，测试亦无需依赖 pytest 即可直接运行。

文件记录器按 Jetson/Linux 本地文件系统实现，使用标准库 `fcntl.flock` 保护单写者及恢复过程，使用文件与目录 `fsync` 保证持久化顺序。离线 PLC 回归使用作用域内的内存传输夹具，无需安装可选 Snap7；原生库通信和现场验收另行验证。

## 4. 当前真实启动方式与线程架构

统一入口文件为根目录的 [main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py)。

### 4.1 启动命令

默认视觉模式先在目标摄像头及目标分辨率下标定：运行 `python3 air_hockey/tools/calibrate_camera.py --cols 10 --rows 7 --square-size 25 --output calibration/camera_calibration.npz` 生成内参，再运行 `python3 air_hockey/tools/calibrate_table.py --output calibration/table_homography.npz` 点击球台四角。摄像头需为 Jetson GStreamer MJPEG 硬解码管道可用的 `/dev/video*` 设备；缺设备/插件/权限会启动失败，不会切到另一采集后端。缺少默认内参或 Homography 文件（以及无效内容）时启动报错，不会自动回退为未校正/线性 ROI；`--sim` 不需要相机。仅调试无标定的采集时显式使用 `python3 main.py --headless --disable-undistort --disable-homography`，该模式不代表正确的台面物理坐标。

1. **默认模式：实时视觉演示（Camera -> Detector -> Tracker -> Geometry -> Kalman -> Predictor -> AI）**
   ```bash
   python3 main.py
   ```
   * 自动打开摄像头，运行背景检测与追踪。
   * 采用微秒级 PPM 协议在 Tkinter 窗口中实时渲染画面、台面 ROI、检测圆、速度矢量、物理预测轨迹、预测终点标记与 AI 拦截准星。

2. **性能压测模式：无显示无头模式（Headless Benchmark）**
   ```bash
   python3 main.py --headless
   python3 main.py --headless --benchmark-seconds 30 --perf-json benchmark.json
   ```
   * 完全关闭 Tkinter 窗口与图像格式转换线程。
   * 纯压测“取帧 -> 抽帧检测/追踪 -> 坐标去畸变 -> 卡尔曼估计 -> 轨迹预测 -> AI 决策”的端到端吞吐率，终端每秒打印处理 FPS 与耗时统计。

3. **仿真游戏模式：启动纯虚拟对战游戏**
   ```bash
   python3 main.py --sim
   # 或
   python3 main.py --game
   ```
   * 启动 [冰壶仿真/air_hockey.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/冰壶仿真/air_hockey.py)，在虚拟桌面上使用鼠标与 AI 进行对战，验证物理反馈与 AI 策略。

4. **运行数据记录模式：输出统一 JSON 日志**
   ```bash
   python3 main.py --record run.json
   ```
   * 逐帧记录 `timestamp / CurlingState / PredictionState / AIDecision / PLC request`，真实运行与仿真格式一致。
   * 运行中写 `run.json.journal` 并逐帧同步磁盘，正常关闭流式生成版本 3 JSON；异常退出的恢复方式见 6.3，不覆盖未恢复日志。

5. **AI -> PLC 运动学模式：后台反馈/下发目标**
   ```bash
   python3 main.py --plc 192.168.0.64 --plc-rate 30
   ```
   * 仅适用与学弟联调版本一致的 S7-1500T DB1/DB18、已标定相机/球台；禁止用 `--disable-homography` 驱动实机。急停与限位必须由 PLC/硬件保障。
   * 安装 3.2 节中的 Snap7 及 setuptools 前置依赖，并确保原生库可加载；连接本身不使能轴，现场人员通过 E/H/C 或图形按钮操作使能、回零与复位。H/C 会立即清除目标及运动授权，操作完成后需重新 E，仿真游戏需手动继续；断线后也需重新使能。`--sim --plc <IP>` 使用同一 PLCLink。
   * 工作线程按 `--plc-rate` 周期读反馈、写心跳与受门禁保护的运动目标；当前视觉→实机完整链路未在目标机器现场复测。
   * 所有上位机控制位采用 [S7 WriteArea / S7WLBit](https://snap7.sourceforge.net/sharp7.html) 的同步按位写入，避免覆盖 PLC/HMI 相邻位。DB 地址不变：先写 `DB1.20..55` 的 36 字节 `[X,0,Y,0] + BufferMode`，成功后单独置 `DB1.56.0`。连接先验证心跳初始化与触发清除的按位写入；失败禁止授权运动。按位原子性不跨多条命令，部分失败不能撤回已接受的位。

### 4.2 常用启动参数说明

* `--headless`：开启无图形界面性能测试；`--benchmark-seconds N` 限时 N 秒退出（默认 0 持续运行），`--perf-json PATH` 退出时保存阶段耗时分布报告。命令在真实标定文件生成后才可不加调试旗标。
* `--preview-fps <fps>`：限制 GUI 预览刷新帧率（默认 20.0），防止 GUI 绘制抢占视觉处理 CPU 资源。
* `--record <path>`：记录运行数据到 JSON 文件（默认关闭）。
* `--plc <IP>` / `--plc-rate <Hz>`：启用 DB1/DB18 运动学闭环并指定通信周期频率（默认关闭 / 30 Hz）。
* `--calibration <path>`：指定相机标定文件（默认 `calibration/camera_calibration.npz`）。
* `--table-calibration <path>`：指定球台四点 Homography 标定文件（默认 `calibration/table_homography.npz`）。
* `--disable-undistort`：关闭相机内参畸变校正（必须同时 `--disable-homography`）。
* `--disable-homography`：显式关闭 Homography 并选择 ROI 线性映射（调试用）；文件缺失或无效时绝不自动选择线性映射。
* `--roi X Y W H`：手动指定相机原始像素下的球台检测区域（默认 `350 0 580 650`）。
* `--lower C1 C2 C3` / `--upper C1 C2 C3`：指定 HSV 颜色阈值范围（默认针对红色冰壶）。

### 4.3 内部多线程协同架构

[main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py) 设计了多线程并行流：

```text
┌─────────────────────────────────────────────────────────────┐
│  CameraManager 采集线程                                     │
│  持续从 GStreamer appsink 抓取帧，线程安全覆盖最新 Frame   │
└──────────────────────────────┬──────────────────────────────┘
                               │ get_latest_frame()
┌──────────────────────────────▼──────────────────────────────┐
│  处理线程 (Processing Thread)                               │
│  1. 取最新帧（遇重复帧自动微休眠 1ms）                      │
│  2. 抽帧机制：每 3 帧做一次 StoneDetector (结合 dynamic_roi) │
│     中间帧由 StoneTracker 按常速模型执行纯几何 predict()    │
│  3. CameraGeometry 将 track 坐标从 raw 转为 table           │
│  4. KalmanFilter 状态估计 → 统一 CurlingState/StoneState    │
│  5. TrajectoryPredictor 输出 PredictionState                │
│  6. PLC 反馈更新实机 AI 球槌位置，AirHockeyAI 输出目标；  │
│     PlcTarget 非阻塞发布至 PLCLink 后台线程              │
│  7. --record 时写运行日志；保存最新 VisionResult 到共享区   │
└──────────────────────────────┬──────────────────────────────┘
                               │ shared["result"]
┌──────────────────────────────▼──────────────────────────────┐
│  编码线程 (Encoding Thread)                                 │
│  按 --preview-fps 限速：缩放原帧至 640 宽 → 在缩图上标注  │
│  转为 RGB PPM (P6 原始二进制格式) → 保存最新 shared["ppm"]│
└──────────────────────────────┬──────────────────────────────┘
                               │ PhotoImage(data=ppm)
┌──────────────────────────────▼──────────────────────────────┐
│  主线程 (Main Thread)                                       │
│  运行 Tkinter mainloop，以 ~30Hz 定时器读取 PPM 刷新显示    │
└─────────────────────────────────────────────────────────────┘
```

状态栏在固定 640 像素宽、64 像素高的容器内换行；追踪激活后较长的状态文本不会改变窗口宽度或使画面居中偏移。

（--plc 时额外启动 PLCLink 周期线程：DB1/DB18 状态读、心跳、已使能/就绪/无报警时的运动触发与反馈位置更新）

## 5. 视觉完整链路与坐标系约定

### 5.1 完整数据处理链路

```text
Camera (1280x720 BGR)
  │
  ▼
StoneDetector (基于 raw 像素坐标)
  │  输入: Frame + 可选 dynamic_roi (raw)
  │  算法: BGR -> HSV -> inRange -> 形态学开闭 -> 外轮廓提取 -> 圆形度与面积综合评分
  ▼
CurlingState (raw: x, y, radius, timestamp, confidence)
  │
  ▼
StoneTracker (基于 raw 像素坐标)
  │  检测帧: update(state) -> 距离匹配 + EMA 速度平滑
  │  跳检帧: predict(timestamp) -> 常速预测 center_x/y，保留 LOST 计数
  ▼
Track (raw: center_x, center_y, vx, vy, state, last_timestamp, confidence)
  │
  ▼
CameraGeometry (逐点坐标转换)
  │  位置: raw -> undistorted (cv2.undistortPoints) -> table（Homography 或线性 ROI）
  ▼
KalmanFilter (状态估计，常量速度模型)
  │  观测: table 位置 + timestamp；检测帧校正，间隔帧外推
  ▼
StoneState / CurlingState (table: x, y, vx, vy, timestamp, confidence, tracking_state)
  │  ← 预测与 AI 共用同一对象，避免同帧重复构造
  ▼
TrajectoryPredictor (微步物理模拟)
  │  输入: CurlingState (table)
  │  模拟: 摩擦阻尼衰减 + 边界四壁反弹 + 门柱圆形碰撞 + 进球穿越判断
  ▼
PredictionState (trajectory / endpoint / duration / source_state)
  │  1. AI 决策消费 table 坐标轨迹
  │  2. 逆变换 table_to_raw() 转换回 raw 像素点用于界面显示
  ▼
AirHockeyAI (输入包含 StoneState 与球槌状态的 GameState)
  │  决策: 守门/前压拦截/回防，输出 AIDecision(target_x, target_y)
  ▼
PlcControlAdapter -> PlcTarget
  │  AI 半场目标 + 坐标检查/限幅/时间戳（不下发冰壶状态/比分）
  ▼
PLCLink (后台周期读写与状态互锁) -> PLCInterface.send_linear_move -> DB1.20 + DB1.56.0
  └── DB1/DB18 的反馈位置与健康状态 -> AI 下一帧
  绘制: table_to_raw 标记 AI 目标十字准星
```

### 5.2 坐标系约定

Kalman 在没有新观测时推进到当前处理帧的时间戳，不回退到旧检测时间。追踪 ID 改变时重建估计，新目标从当前观测位置、零速度初始化；无轨迹时仍清空估计。

系统中存在三个严格定义的独立坐标系，禁止任何跨坐标系的坐标混用与手工 offset 叠加：

| 坐标系 | 英文标识 | 原点位置 | 单位 | 职责范围 |
|---|---|---|---|---|
| **原始图像坐标系** | `raw` | 相机传感器画幅左上角 `(0, 0)` | 像素 (`pixel`) | `StoneDetector`、`StoneTracker`、`dynamic_roi`、最终界面标注。所有检测和追踪算法只在 raw 像素下运算，不承受任何图像校正带来的形变或裁剪偏差。 |
| **去畸变像素坐标系** | `undistorted` | 经内参矩阵去畸变后的无形变投影平面 | 像素 (`pixel`) | `CameraGeometry` 内部中间态。通过标定相机矩阵与畸变参数数学计算，**不执行整图 remap 像素重采样**，仅针对特征点做数学反投影。 |
| **球台物理/场地坐标系** | `table` / `rink` | 球台左上角物理顶点 `(RINK_LEFT, RINK_TOP)` | 毫米 / 场地逻辑单位 | `TrajectoryPredictor` 物理仿真、`GameState` 数据契约、`AirHockeyAI` 决策、PLC 下发坐标。 |

#### 速度转换约定：空间微元差分
去畸变属于非线性几何变换，简单的线性缩放乘法会导致畸变区域的速度矢量失真。因此 `CameraGeometry.raw_velocity_to_table` 统一使用有限差分法：

$$\vec{v}_{\text{table}} = \frac{\text{raw\_to\_table}(\vec{p}_{\text{raw}} + \vec{v}_{\text{raw}} \cdot \Delta t) - \text{raw\_to\_table}(\vec{p}_{\text{raw}})}{\Delta t} \quad (\Delta t = 0.01\text{s})$$

保证位置与速度使用同一套坐标映射管线，彻底消除速度与位置的比例尺漂移。

> [!NOTE]
> `undistorted` $\rightarrow$ `table` 默认使用球台四点透视单应矩阵（`calibrate_table.py` 标定），文件缺失/不匹配时报错，不自动回退。仅显式 `--disable-homography` 使用基于 `table_roi` 的轴对齐线性缩放（调试用）；同时关闭去畸变必须再显式传 `--disable-undistort`。完整坐标流为 `raw pixel` -> `undistorted pixel` -> `table/rink`。

## 6. 统一轨迹物理说明与预测核心

目前全项目的物理预测核心统一收敛于 [air_hockey/prediction/predictor.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/prediction/predictor.py) 中的 `TrajectoryPredictor`。

### 6.1 统一物理特性
`TrajectoryPredictor` 采用微步前向欧拉迭代（默认步长 `PREDICTION_SUBSTEP = 1/240 s`），完整模拟真实台面物理规律：
1. **真实摩擦阻尼**：每一微步根据当前速度大小衰减速度，速度小于 `STONE_STOP_SPEED` 时精确刹停。
2. **四周边界反弹**：检测左、右、上、下反弹墙，撞墙后切向速度保留、法向速度按弹性恢复系数 `WALL_RESTITUTION` 反向折减。
3. **球门开口穿透**：球门横向范围 `[GOAL_LEFT, GOAL_RIGHT]` 内不产生后墙反弹，当冰壶整体穿过底线时立即触发得分并终止预测。
4. **圆形门柱碰撞**：球门两侧端柱具有实体半径，冰壶撞击门柱产生精确的圆-圆切线弹性反弹。
5. **障碍物拦截**：支持注入球槌或阻挡物坐标，发生碰撞时截断轨迹。

预测副本的当前及目标速度在第一次位置推进前都限制到 `MAX_STONE_SPEED`，保留响应状态且不改输入对象。轨迹一直计算到停止、进球或障碍接触，`endpoint` 精确保留终态位置，`duration` 为完整物理时长，不再被绘制点数或反弹次数截断。构造参数仅保留 `substep / point_interval / max_simulation_steps / stop_speed`，删除 `max_points / max_bends` 及对应核心配置，没有兼容别名。默认预算 4000 微步（默认步长下约 16.67 秒），耗尽时抛出 `RuntimeError`，不返回假终点。

无摄像头 `MotionSimulator.true_trajectory()` 复用门柱与进球规则，得分后保持得分位置到末帧，轨迹和时间戳仍有 `steps + 1` 项。仿真与评估配置均拒绝非有限或非正 `dt`，以及非有限或负的噪声。完整预测的 CPU 开销须在目标 Jetson 实测，不能以本机耗时代替现场处理 FPS。

### 6.2 仿真、视觉、AI、控制四端共用
* **仿真端 ([air_hockey.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/冰壶仿真/air_hockey.py))**：物理推演实体与玩家击球预测均调用 `TrajectoryPredictor`。
* **视觉端 ([main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py))**：Kalman 平滑后的 `CurlingState` 传入 Predictor 得到 `PredictionState`，轨迹经 `table_to_raw` 在画面中绘制渐变预测虚线，`endpoint` 绘制预测终点标记。
* **AI 决策端 ([air_hockey/ai.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/ai.py))**：实时防守复用本帧 `PredictionState.trajectory` 搜索拦截线；独立仿真调用可自行运行 Predictor。
* **控制端 ([air_hockey/control](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/control/adapter.py))**：S7-1500T DB1 接收实际 mm 坐标与运动触发，DB18 通信状态回传；仅下发 AI 半场目标，独立 `planning/` 模块不参与下发。

### 6.3 统一状态与运行日志
* `CurlingState`（位置/速度/时间戳/置信度）是视觉、估计、预测、控制共享的状态模型；`StoneState` 仅额外携带 `tracking_state`。VisionRuntime 每帧只产出**一份**权威状态，预测与 AI 共用同一对象。
* `PredictionState` 打包一次预测的 `trajectory / endpoint / duration / source_state`，业务层不再直接传递裸点列表。
* `--record <path>` 输出统一格式运行日志（`air_hockey/recording`），真实运行与仿真格式一致，逐帧包含 `curling_state / prediction / ai_decision / plc_request`，便于离线复现与误差分析。

设置输出路径后，元数据和帧逐行写入 `<path>.journal`，每帧 `flush` + `fsync`；正常关闭时流式导出版本 3 JSON，持久化成功后才删除日志，内存不随运行时长增长。导出失败保留日志且可以重试 `close()`。显式 `to_dict()` / `to_json()` 会读入全部帧；没有路径的有限长度离线记录仍在内存。导出时日志和 JSON 共存，须留出额外磁盘空间；每帧同步可能降低处理 FPS。

进程异常退出后，确认旧进程已经退出，再执行：

```bash
python3 -c "from air_hockey.recording import RuntimeRecorder; RuntimeRecorder.recover('run.json')"
```

恢复只忽略末尾未写完的一行；完整行损坏或帧序号不连续会报错并保留日志。文件锁拒绝恢复仍在运行的记录，同路径新记录器拒绝覆盖未恢复日志。`main.py` 在标定及相机启动成功后才创建记录器，标定或相机启动失败不会创建日志；`--sim` 也传播游戏子进程的退出状态。

## 7. 当前已完成与未完成内容

### 7.1 当前已完成内容
1. **高性能相机驱动与采集层**：
   * 仅支持 PyGObject GStreamer appsink 硬件解码抓流；缺设备、插件或首帧失败会呈现故障，不自动降级。
   * 独立采集线程 + 线程安全单帧覆盖缓存，业务端获取最新帧；尚无本次变更的 Jetson 实机 FPS/时延测量。
2. **目标检测模块 (StoneDetector)**：
   * 基于 HSV/Lab 颜色分量与多边形轮廓拟合。
   * 支持圆形度、面积、半径阈值过滤与启发式加权优选。
   * 支持每帧传入 `dynamic_roi`，利用预测位置进行局部裁剪检测。
3. **目标追踪模块 (StoneTracker)**：
   * 运行在原始像素坐标系下的常速运动模型。
   * 采用时间戳差分与指数平滑滤波器（EMA）消除速度噪点。
   * 支持目标丢失判定、短时漏检预测维持与自动注销。
4. **相机几何校正层 (CameraGeometry)**：
   * 基于标定参数矩阵的单目去畸变算法。
   * 点级双向映射（`raw <-> undistorted <-> table`），免除高开销整图插值。
   * `undistorted <-> table` 支持球台四点透视单应矩阵（`calibrate_table.py` 标定），并可回退线性 ROI。
   * 空间有限微元差分速度映射。
5. **卡尔曼状态估计层 (KalmanFilter)**：
   * 常量速度模型（`[px, py, vx, vy]`）融合位置观测序列，输出平滑 `CurlingState`。
   * 检测帧观测校正、检测间隔帧模型外推、丢轨时 reset；显著降低视觉抖动。
6. **统一物理、预测、规划与控制闭环**：
   * 物理轨迹预测核心统一并收敛至 `TrajectoryPredictor`，输出 `PredictionState`。
   * 实时链：`AIDecision` -> `PlcControlAdapter` -> `PlcTarget` -> `PLCLink`（周期反馈/互锁/触发）-> `PLCInterface`；轴反馈返回 `VisionRuntime`，独立 `TrajectoryPlanner` 不参与 PLC 下发。
   * 坐标限制于 AI 半场并换算为机械 mm；`DB1.20` 从 `Position[1]`、`Position[3]` 写入 X/Y，DB 无时间戳或独立速度指令。
   * Tkinter 零压缩 PPM 高速渲染管道与无头测试模式。
7. **仿真 / 评估 / 记录工具链**：
   * `simulation/`：无摄像头运动仿真（真实轨迹 -> 观测 -> Kalman -> 预测 -> 误差）。
   * `evaluation/`：多组实验误差评估与 JSON / 控制台报告。
   * `recording/`：真实/仿真统一格式运行日志（CurlingState / PredictionState / AIDecision / PLC request）。
8. **自动化单元测试集**：
   * 根目录 `tests/` 覆盖 GStreamer 采集故障传播、AI 决策、状态映射、卡尔曼估计、几何畸变差分、物理模拟、PLC 运动互锁、记录格式、仿真评估、渲染与追踪器逻辑。

### 7.2 当前未完成内容
1. **实台物理特性参数标定**：
   * 当前台面摩擦力、恢复系数与球槌打击响应曲线来源于仿真参数，未与实机气浮台冰壶的真实滑行轨迹进行数据拟合。

## 9. 真机运行与调试注意事项

1. **Jetson 功耗模式与性能锁频**：
   * Jetson Xavier NX 初始状态可能处于 `MODE_20W_2CORE`（仅开启 2 个 CPU 核心）。
   * 必须通过 root 权限切换至全部 6 核心模式并锁频：
     ```bash
     sudo nvpmodel -m 8     # 切换至 20W_6CORE 模式（需核对 nvpmodel -q --verbose）
     sudo bash air_hockey/tools/pre_test.sh # 执行手动锁频脚本，确保 CPU/GPU/EMC 调度器全切至 performance
     ```
   * **EMC（内存控制器）频率对高帧率图像从 DMA/硬件解码缓冲区拷贝至 CPU 内存带宽至关重要**，必须锁在最高频。

2. **高帧率相机与解码带宽**：
   * 摄像头标称 200 FPS 时，原生 GStreamer 管道为：
     `MJPG -> nvv4l2decoder -> nvvidconv -> BGRx -> appsink -> CPU BGR`
   * OpenCV BGRx→BGR 转换仍占用 CPU；预览先缩图再绘制，减少全分辨率画面的复制和绘制。可用 `--preview-fps 20` 限制 GUI 刷新，或直接运行 `--headless`。更改 Jetson 解码/协商格式须先在实机比较吞吐，不能用本机合成图像的转换耗时推断。

3. **光照与冰面反光应对**：
   * 气浮台桌面反光和室内光源色温会显著改变 HSV 色域分布。
   * 在实机开机前，必须使用工具重新标定冰壶颜色阈值：
     ```bash
     # 采集单张实况照片并调整阈值
     python3 air_hockey/tools/test_image.py <frame.jpg> --output /tmp/result.jpg --lower 170 100 80 --upper 179 255 255
     ```

4. **无显示器 (Headless) 运行**：
   * 通过 SSH 登录 Jetson 调试时，若未挂载 X11 会话，请勿执行带 GUI 的命令，直接添加 `--headless`：
     ```bash
     python3 main.py --headless
     ```

所有测试与诊断工具均可在项目根目录下直接运行：

```bash
python3 tests/run_tests.py
```
若环境中已安装 pytest，亦可执行：
```bash
pytest tests/
```

### 10.2 语法与字节码完整性检查
```bash
python3 -m compileall -q air_hockey tests 冰壶仿真 main.py game_state.py
```

### 10.3 常用诊断与测试工具

* **相机纯采集性能压测**：
  ```bash
  python3 air_hockey/tools/test_camera.py --benchmark --duration 10
  ```
  输出设备、请求参数与 caps 实际协商分辨率/帧率、采集线程记录的实测采集 FPS、最新帧去重样本的 read/convert 耗时分布；read 总耗时包含 appsink 等待及转换，不能与 convert 再相加。去重样本可能跳过帧，不能直接代替整体帧计数。相机报错时非零退出，不再选择备用采集后端。
* **视觉链路分阶段报告**（先按 4.1 完成标定）：
  ```bash
  python3 main.py --headless --benchmark-seconds 30 --perf-json benchmark.json
  ```
  无标定时仅作采集/计算链调试需显式追加 `--disable-undistort --disable-homography`，不可用来验证正确的球台坐标。报告阶段 p50/p95/max 与 FPS 是不同量：请求/协商 FPS 并非实际采集 FPS，实际采集 FPS 亦非视觉处理 FPS。`Frame.timestamp` 为读取并颜色转换后的 host `perf_counter`，不等于曝光时刻；`gst_pts_ns` 是未映射时钟域的原始 GStreamer PTS，不能直接与 host 时刻相减。任何曝光到显示/PLC 的真实端到端延迟仍需设备同步与实机测量；当前环境无 Jetson，不提供这类实测结论。
* **GStreamer 内存传输损耗评估**：
  ```bash
  python3 air_hockey/tools/test_gstreamer_transfer.py --mode bgr-cvt --duration 10
  ```
  `bgr-cvt` 测独立 appsink 管道的 map 与后端相同的 OpenCV BGRx→BGR 转换；`bgr-copy` 只测 NumPy 三通道裁剪复制。两者均不包含完整 `GStreamerBackend.read()` 的协商/故障检查和 CameraManager 采集/覆盖路径，其 FPS 不等于应用采集 FPS。
* **相机内参交互式棋盘格标定**：
  ```bash
  python3 air_hockey/tools/calibrate_camera.py --cols 10 --rows 7 --square-size 25 --output calibration/camera_calibration.npz
  ```
   始终自动采样，不再接受无效的 `--auto`；重复帧不重新检测或采样，仍响应退出键。采集报错立即退出并清理相机，不继续显示陈旧缓存。
* **球台四点 Homography 标定**：
  ```bash
  python3 air_hockey/tools/calibrate_table.py --output calibration/table_homography.npz
  ```
* **无摄像头轨迹仿真（真实/观测/滤波/预测终点）**：
  ```bash
  python3 air_hockey/simulation/run_simulation.py
  ```
* **多组实验误差评估（JSON + 控制台报告）**：
  ```bash
  python3 air_hockey/evaluation/run_evaluation.py --runs 5
  ```
* **离线图像颜色检测标定**：
  ```bash
  python3 air_hockey/tools/test_image.py <image_path> --output /tmp/detect.jpg --roi 350 0 580 650
  ```
* **轨迹预测独立功能测试**：
  ```bash
  python3 air_hockey/tools/test_prediction.py
  ```
* **纯视觉检测与追踪可视化验证**：
  ```bash
  python3 air_hockey/tools/test_tracker.py
  ```
* **离线仿真驱动的 AI 闭环验证**：
  ```bash
  python3 air_hockey/tools/test_ai_pipeline.py --visualize
  ```

## 11. 当前技术债务清单

为便于后续版本规划，当前存在的明确技术债务梳理如下：

### 11.1 实机物理参数未经系统辨识标定
* **现状**：[air_hockey/core_config.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/core_config.py) 中的摩擦系数、边墙弹性系数与球槌打击响应曲线基于虚拟游戏手感设定，未经真实台面数据拟合。
* **解法**：在真实冰台上释放不同初速度的冰壶，利用视觉系统记录实际运动衰减与碰撞反射点，通过最小二乘法回归出真实台面的物理参数；可复用 `air_hockey/evaluation` 做误差评估。

### 11.2 追踪状态机未细化（多目标支持缺失）
* **现状**：[tracker.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/vision/tracker.py) 仅有 `ACTIVE` / `LOST` 两种状态，且按单冰壶设计。速度平滑现由 `KalmanFilter` 承担，但追踪器本身仍缺少暂态/确认/遮挡预测等状态。
* **问题**：冰壶被球槌瞬间击打或短时穿过强反光区时，目标关联可能抖动或丢失；多冰壶场景无法区分。
* **解法**：细化状态机（TENTATIVE -> CONFIRMED -> OCCLUDED -> LOST），并引入多目标关联（匈牙利算法 / IOU 匹配）。

### 11.3 视觉 AI -> PLC 整链路尚未现场验收
* **现状**：实机 DB1/DB18 协议与轴映射以学弟联调代码为准；`main.py --plc` 的视觉目标、PLCLink 运动触发与反馈驱动 AI 已合并，但视觉→机构现场验收尚未完成。
* **问题**：缺少曝光到轴到位的端到端时延数据；视觉球台坐标与机械行程方向、回零使能状态及硬件急停仍须现场核对。共享字节现由上位机同步按位写入，但实际 PLC 的按位权限、扫描周期、脉宽及 PLC/HMI 自身写入方式仍须复核；部分命令失败不能撤回已接受的位，软件暂停也不能撤回已发送的运动指令。
* **解法**：保留现有 DB 地址，先核对按位接口、TIA DB 布局、限位和硬件急停，再低速核对 `[X,0,Y,0]` 目标方向、分步测量响应和标定。急停、失联停机由 PLC/硬件独立完成；本地原生 S7 通信与回归测试不能代替现场验收。

### 11.4 缺乏自动化持续集成（CI）
* **现状**：项目当前仅通过本地 `python3 tests/run_tests.py` 执行测试，未搭建远端 CI。
* **解法**：添加 `.github/workflows/ci.yml`，在推流或提 PR 时自动执行 `compileall` 与轻量化单元测试。

### 11.5 标定与部署流程缺乏向导化封装
* **现状**：相机内参标定（`calibrate_camera.py`）、球台四点 Homography 标定（`calibrate_table.py`）、颜色阈值设置是割裂的独立脚本。
* **解法**：开发面向现场调试的一键式向导工具，串联棋盘格内参标定、台面四角点点击标定和冰壶色域自适应提取，并封装 Jetson 开机自启服务。
