# Air Hockey 项目交接文档

## 1. 项目概述与当前阶段

本项目为基于计算机视觉与嵌入式硬件的空气冰壶实时目标检测、运动轨迹追踪与 AI 决策系统，主要部署于 NVIDIA Jetson 边缘计算平台，下行对接西门子 PLC 执行机构。

当前系统已全面打通从相机采集、视觉检测、动态目标追踪、相机几何去畸变、卡尔曼状态估计、统一物理轨迹预测、AI 防守决策到 PLC 控制输出的完整端到端链路：

```text
Camera (CameraManager / GStreamer appsink)
  │ (Frame: raw BGR)
  ▼
StoneDetector (HSV/Lab + 轮廓几何约束，基于 raw 坐标，支持 dynamic_roi)
  │ (CurlingState: raw pixel + confidence)
  ▼
StoneTracker (常速模型，运行于 raw 坐标，负责关联与 dynamic_roi)
  │ (Track: raw center & velocity)
  ▼
CameraGeometry (逐点去畸变 raw -> undistorted -> table；支持四点 Homography)
  │ (table 坐标)
  ▼
KalmanFilter (常量速度模型状态估计，抑制视觉抖动)
  │ (CurlingState / StoneState: table 坐标与速度)
  ▼
TrajectoryPredictor (统一物理微步模拟：摩擦阻尼、弹墙、门柱碰撞、进球判定)
  │ (PredictionState: trajectory / endpoint / duration / source_state)
  ▼
AirHockeyAI (基于预测轨迹计算拦截点与击球决策)
  │ (AIDecision: target_x, target_y)
  ▼
TrajectoryPlanner -> PlcControlAdapter (规划 + 坐标检查/限幅/时间戳)
  │ (ControlCommand -> PlcWriteRequest)
  ▼
PlcOutputWorker (非阻塞) -> PLCInterface (S7 DB1，可选 --plc)
```

项目当前处于**实机视觉与算法闭环、状态估计、Homography 校正与 AI→PLC 非阻塞控制闭环均已打通，待开展实台物理参数辨识与实机运动联调**的阶段。

### 1.1 模块依赖方向

视觉运行链的模块依赖方向如下（`VisionRuntime` 作为运行核心，编排检测、追踪、坐标几何、卡尔曼状态估计、轨迹预测、AI 决策与可选 PLC 输出）：

```text
Camera
  -> VisionRuntime
       -> Detector
       -> Tracker
       -> KalmanFilter
       -> CameraGeometry
       -> TrajectoryPredictor
       -> AirHockeyAI
       -> PlcControlAdapter (可选，仅 --plc 时启用)
```

> 视觉核心（`Camera` / `VisionRuntime` / `Detector` / `Tracker` / `KalmanFilter` / `CameraGeometry` / `TrajectoryPredictor` / `AirHockeyAI`）**不依赖 `冰壶仿真/` 目录**。共享物理（`physics`）、AI（`ai`）、状态契约（`game_state`）、预测（`prediction`）、估计（`estimation`）、规划（`planning`）、控制（`control`）与配置（`core_config`）均已归位于 `air_hockey/` 包内；仿真目录仅保留仿真 GUI、GUI 配置与 `PLCInterface` 通信模块。

## 3. 依赖环境说明

系统在开发与部署时严格区分 **普通 Python 依赖** 与 **Jetson 平台系统级依赖**。禁止引入代码未实际调用的冗余库。

### 3.1 Python 版本
* **要求**：`Python >= 3.8`
* **目标环境**：Jetson Xavier NX 生产环境运行于 `Python 3.8.10`（Ubuntu 20.04 LTS）。
* **代码兼容性规范**：核心算法与模型保持向后兼容，不使用仅在 3.10+ 支持的 `slots=True` 特性或强制的联合类型运行时语法，保证在 Jetson 预装 Python 3.8 下可免升级直接运行。

### 3.2 普通 Python 依赖（通过 pip 或系统 apt 安装）
* `numpy` (`>= 1.17.4`)：矩阵与几何变换、标定参数序列化（`.npz` 读写）。
* `opencv-python` / `python3-opencv` (`>= 4.5.0`)：图像颜色空间转换、轮廓提取、内参去畸变（`cv2.undistortPoints`、`cv2.projectPoints`）。
* `python-snap7`（可选，对接 PLC 时必需）：通过 S7 协议向西门子 S7-1200/1500 PLC DB 块读写游戏与打击坐标。
* `tkinter`（Python 标准库 / `python3-tk`）：主界面 GUI 与仿真窗口显示。

### 3.3 Jetson / Linux 系统级依赖
* `python3-gi` (PyGObject)：提供 `gi.repository.Gst` 接口。`GStreamerBackend` 优先通过原生 appsink 直接获取图像内存指针，跳过 OpenCV 中间适配层，显著降低高帧率下 CPU 占用。
* `gstreamer1.0-*` 运行环境：
  * `libgstreamer1.0-0`
  * `gstreamer1.0-plugins-base`
  * `gstreamer1.0-plugins-good`
  * `gstreamer1.0-plugins-bad`
* NVIDIA Jetson 硬件多媒体编解码库：
  * `nvidia-l4t-gstreamer`：包含硬件加速元件 `nvarguscamerasrc`、`nvv4l2decoder`、`nvvidconv`、`nveglglessink`。
* `v4l-utils`：提供 `v4l2-ctl`，用于查询摄像头支持的硬件分辨率与格式。
* `libsnap7-dev` / `libsnap7.so`：若使用 S7 通信，Linux 系统层需存在 snap7 动态库。

> [!NOTE]
> 项目不依赖 PyTorch、TensorFlow、ONNX Runtime 等深度学习推理引擎，测试亦无需依赖 pytest 即可直接运行。

## 4. 当前真实启动方式与线程架构

统一入口文件为根目录的 [main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py)。

### 4.1 启动命令

1. **默认模式：实时视觉演示（Camera -> Detector -> Tracker -> Geometry -> Kalman -> Predictor -> AI）**
   ```bash
   python3 main.py
   ```
   * 自动打开摄像头，运行背景检测与追踪。
   * 采用微秒级 PPM 协议在 Tkinter 窗口中实时渲染画面、台面 ROI、检测圆、速度矢量、物理预测轨迹、预测终点标记与 AI 拦截准星。

2. **性能压测模式：无显示无头模式（Headless Benchmark）**
   ```bash
   python3 main.py --headless
   ```
   * 完全关闭 Tkinter 窗口与图像格式转换线程。
   * 纯压测“取帧 -> 抽帧检测/追踪 -> 坐标去畸变 -> 卡尔曼估计 -> 轨迹预测 -> AI 决策”的端到端吞吐率，终端每秒打印处理 FPS 与耗时统计。

3. **仿真游戏模式：启动纯虚拟对战游戏**
   ```bash
   python3 main.py --sim
   # 或
   python3 main.py --game
   ```
   * 启动 [冰壶仿真/air_hockey.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/冰壶仿真/air_hockey.py)，在虚拟桌面上使用鼠标与 AI 进行对战，验证物理反馈与 AI 策略。

4. **运行数据记录模式：输出统一 JSON 日志**
   ```bash
   python3 main.py --record run.json
   ```
   * 逐帧记录 `timestamp / CurlingState / PredictionState / AIDecision / PLC request`，真实运行与仿真格式一致。

5. **AI -> PLC 输出模式：非阻塞写入 S7 PLC**
   ```bash
   python3 main.py --plc 192.168.0.1 --plc-rate 30
   ```
   * 需要安装 `python-snap7` 且 PLC 可达；未连接时仅提示并跳过，不影响视觉链路。
   * 处理线程只投递最新请求，实际写入由后台线程按 `--plc-rate` 限速完成。

### 4.2 常用启动参数说明

* `--headless`：开启无图形界面性能测试。
* `--preview-fps <fps>`：限制 GUI 预览刷新帧率（默认 20.0），防止 GUI 绘制抢占视觉处理 CPU 资源。
* `--record <path>`：记录运行数据到 JSON 文件（默认关闭）。
* `--plc <IP>` / `--plc-rate <Hz>`：启用 AI->PLC 非阻塞输出并指定写入频率上限（默认关闭 / 30 Hz）。
* `--calibration <path>`：指定相机标定文件（默认 `calibration/camera_calibration.npz`）。
* `--table-calibration <path>`：指定球台四点 Homography 标定文件（默认 `calibration/table_homography.npz`）。
* `--disable-undistort`：关闭相机内参畸变校正（必须同时 `--disable-homography`）。
* `--disable-homography`：关闭 Homography，回退到旧 ROI 线性映射（调试用）。
* `--roi X Y W H`：手动指定相机原始像素下的球台检测区域（默认 `350 0 580 650`）。
* `--lower C1 C2 C3` / `--upper C1 C2 C3`：指定 HSV 颜色阈值范围（默认针对红色冰壶）。

### 4.3 内部多线程协同架构

[main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py) 设计了多线程并行流：

```text
┌─────────────────────────────────────────────────────────────┐
│  CameraManager 采集线程                                     │
│  持续从 GStreamer/V4L2 抓取最新帧，无锁写入 FrameBuffer     │
└──────────────────────────────┬──────────────────────────────┘
                               │ get_latest_frame()
┌──────────────────────────────▼──────────────────────────────┐
│  处理线程 (Processing Thread)                               │
│  1. 取最新帧（遇重复帧自动微休眠 1ms）                      │
│  2. 抽帧机制：每 3 帧做一次 StoneDetector (结合 dynamic_roi) │
│     中间帧由 StoneTracker 按常速模型执行纯几何 predict()    │
│  3. CameraGeometry 将 track 坐标从 raw 转为 table           │
│  4. KalmanFilter 状态估计 → 统一 CurlingState/StoneState    │
│  5. TrajectoryPredictor 输出 PredictionState                │
│  6. AirHockeyAI 刷新 AIDecision；可选构建 ControlCommand →  │
│     PlcWriteRequest 并 submit() 给 PLC 输出线程（非阻塞）   │
│  7. --record 时写运行日志；保存最新 VisionResult 到共享区   │
└──────────────────────────────┬──────────────────────────────┘
                               │ shared["result"]
┌──────────────────────────────▼──────────────────────────────┐
│  编码线程 (Encoding Thread)                                 │
│  按 --preview-fps 限速：render 标注 → 降采样 640 宽 →       │
│  直接转为 PPM (P6 原始二进制格式)，微秒级写入 shared["ppm"] │
└──────────────────────────────┬──────────────────────────────┘
                               │ PhotoImage(data=ppm)
┌──────────────────────────────▼──────────────────────────────┐
│  主线程 (Main Thread)                                       │
│  运行 Tkinter mainloop，以 ~30Hz 定时器读取 PPM 刷新显示    │
└─────────────────────────────────────────────────────────────┘

（--plc 时额外启动 PLC 输出线程：按 --plc-rate 取最新 PlcWriteRequest 写入 PLC）
```

## 5. 视觉完整链路与坐标系约定

### 5.1 完整数据处理链路

```text
Camera (1280x720 BGR)
  │
  ▼
StoneDetector (基于 raw 像素坐标)
  │  输入: Frame + 可选 dynamic_roi (raw)
  │  算法: BGR -> HSV -> inRange -> 形态学开闭 -> 外轮廓提取 -> 圆形度与面积综合评分
  ▼
CurlingState (raw: x, y, radius, timestamp, confidence)
  │
  ▼
StoneTracker (基于 raw 像素坐标)
  │  检测帧: update(state) -> 距离匹配 + EMA 速度平滑
  │  跳检帧: predict(timestamp) -> 常速预测 center_x/y，保留 LOST 计数
  ▼
Track (raw: center_x, center_y, vx, vy, state, last_timestamp, confidence)
  │
  ▼
CameraGeometry (逐点坐标转换)
  │  位置: raw -> undistorted (cv2.undistortPoints) -> table（Homography 或线性 ROI）
  ▼
KalmanFilter (状态估计，常量速度模型)
  │  观测: table 位置 + timestamp；检测帧校正，间隔帧外推
  ▼
StoneState / CurlingState (table: x, y, vx, vy, timestamp, confidence, tracking_state)
  │  ← 预测与 AI 共用同一对象，避免同帧重复构造
  ▼
TrajectoryPredictor (微步物理模拟)
  │  输入: CurlingState (table)
  │  模拟: 摩擦阻尼衰减 + 边界四壁反弹 + 门柱圆形碰撞 + 进球穿越判断
  ▼
PredictionState (trajectory / endpoint / duration / source_state)
  │  1. AI 决策消费 table 坐标轨迹
  │  2. 逆变换 table_to_raw() 转换回 raw 像素点用于界面显示
  ▼
AirHockeyAI (输入包含 StoneState 与球槌状态的 GameState)
  │  决策: 守门/前压拦截/回防，输出 AIDecision(target_x, target_y)
  ▼
TrajectoryPlanner -> PlcControlAdapter -> PlcWriteRequest
  │  ControlCommand(target_position, direction, speed) + 坐标检查/限幅/时间戳
  ▼
PlcOutputWorker (非阻塞) -> PLCInterface.write_game_state -> S7 DB1
  绘制: table_to_raw 标记 AI 目标十字准星
```

### 5.2 坐标系约定

系统中存在三个严格定义的独立坐标系，禁止任何跨坐标系的坐标混用与手工 offset 叠加：

| 坐标系 | 英文标识 | 原点位置 | 单位 | 职责范围 |
|---|---|---|---|---|
| **原始图像坐标系** | `raw` | 相机传感器画幅左上角 `(0, 0)` | 像素 (`pixel`) | `StoneDetector`、`StoneTracker`、`dynamic_roi`、最终界面标注。所有检测和追踪算法只在 raw 像素下运算，不承受任何图像校正带来的形变或裁剪偏差。 |
| **去畸变像素坐标系** | `undistorted` | 经内参矩阵去畸变后的无形变投影平面 | 像素 (`pixel`) | `CameraGeometry` 内部中间态。通过标定相机矩阵与畸变参数数学计算，**不执行整图 remap 像素重采样**，仅针对特征点做数学反投影。 |
| **球台物理/场地坐标系** | `table` / `rink` | 球台左上角物理顶点 `(RINK_LEFT, RINK_TOP)` | 毫米 / 场地逻辑单位 | `TrajectoryPredictor` 物理仿真、`GameState` 数据契约、`AirHockeyAI` 决策、PLC 下发坐标。 |

#### 速度转换约定：空间微元差分
去畸变属于非线性几何变换，简单的线性缩放乘法会导致畸变区域的速度矢量失真。因此 `CameraGeometry.raw_velocity_to_table` 统一使用有限差分法：

$$\vec{v}_{\text{table}} = \frac{\text{raw\_to\_table}(\vec{p}_{\text{raw}} + \vec{v}_{\text{raw}} \cdot \Delta t) - \text{raw\_to\_table}(\vec{p}_{\text{raw}})}{\Delta t} \quad (\Delta t = 0.01\text{s})$$

保证位置与速度使用同一套坐标映射管线，彻底消除速度与位置的比例尺漂移。

> [!NOTE]
> `undistorted` $\rightarrow$ `table` 支持两种模式：配置了 `table_homography.npz` 时使用球台四点透视单应矩阵（`calibrate_table.py` 标定），否则回退为基于球台 `table_roi` 的轴对齐线性缩放。完整坐标流为 `raw pixel` -> `undistorted pixel` -> `table/rink`。若要回退线性映射（调试用），启动时传 `--disable-homography`。

## 6. 统一轨迹物理说明与预测核心

目前全项目的物理预测核心统一收敛于 [air_hockey/prediction/predictor.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/prediction/predictor.py) 中的 `TrajectoryPredictor`。

### 6.1 统一物理特性
`TrajectoryPredictor` 采用微步前向欧拉迭代（默认步长 `PREDICTION_SUBSTEP = 1/240 s`），完整模拟真实台面物理规律：
1. **真实摩擦阻尼**：每一微步根据当前速度大小衰减速度，速度小于 `STONE_STOP_SPEED` 时精确刹停。
2. **四周边界反弹**：检测左、右、上、下反弹墙，撞墙后切向速度保留、法向速度按弹性恢复系数 `WALL_RESTITUTION` 反向折减。
3. **球门开口穿透**：球门横向范围 `[GOAL_LEFT, GOAL_RIGHT]` 内不产生后墙反弹，当冰壶整体穿过底线时立即触发得分并终止预测。
4. **圆形门柱碰撞**：球门两侧端柱具有实体半径，冰壶撞击门柱产生精确的圆-圆切线弹性反弹。
5. **障碍物拦截**：支持注入球槌或阻挡物坐标，发生碰撞时截断轨迹。

### 6.2 仿真、视觉、AI、控制四端共用
* **仿真端 ([air_hockey.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/冰壶仿真/air_hockey.py))**：物理推演实体与玩家击球预测均调用 `TrajectoryPredictor`。
* **视觉端 ([main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py))**：Kalman 平滑后的 `CurlingState` 传入 Predictor 得到 `PredictionState`，轨迹经 `table_to_raw` 在画面中绘制渐变预测虚线，`endpoint` 绘制预测终点标记。
* **AI 决策端 ([air_hockey/ai.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/ai.py))**：AI 内部统一注入 `TrajectoryPredictor`；防守决策在 `PredictionState.trajectory` 中搜索防守线横坐标，实现对多重弹墙球与折射球的高精度预判拦截。
* **控制端 ([air_hockey/planning](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/planning/trajectory_planner.py) / [air_hockey/control](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/control/adapter.py))**：`TrajectoryPlanner` 用预测时长换算 `ControlCommand.speed`，`PlcControlAdapter` 再做坐标范围检查、输出限幅与时间戳封装。

### 6.3 统一状态与运行日志
* `CurlingState`（位置/速度/时间戳/置信度）是视觉、估计、预测、控制共享的状态模型；`StoneState` 仅额外携带 `tracking_state`。VisionRuntime 每帧只产出**一份**权威状态，预测与 AI 共用同一对象。
* `PredictionState` 打包一次预测的 `trajectory / endpoint / duration / source_state`，业务层不再直接传递裸点列表。
* `--record <path>` 输出统一格式运行日志（`air_hockey/recording`），真实运行与仿真格式一致，逐帧包含 `curling_state / prediction / ai_decision / plc_request`，便于离线复现与误差分析。

## 7. 当前已完成与未完成内容

### 7.1 当前已完成内容
1. **高性能相机驱动与采集层**：
   * 支持原生 PyGObject GStreamer appsink 硬件解码抓流（1280x720 MJPG 实测采集超 140 FPS）。
   * 支持 V4L2 / OpenCV 后端自动降级。
   * 独立的守护采集线程，保证业务端永远获取最新无堆积帧。
2. **目标检测模块 (StoneDetector)**：
   * 基于 HSV/Lab 颜色分量与多边形轮廓拟合。
   * 支持圆形度、面积、半径阈值过滤与启发式加权优选。
   * 支持每帧传入 `dynamic_roi`，利用预测位置进行局部裁剪检测。
3. **目标追踪模块 (StoneTracker)**：
   * 运行在原始像素坐标系下的常速运动模型。
   * 采用时间戳差分与指数平滑滤波器（EMA）消除速度噪点。
   * 支持目标丢失判定、短时漏检预测维持与自动注销。
4. **相机几何校正层 (CameraGeometry)**：
   * 基于标定参数矩阵的单目去畸变算法。
   * 点级双向映射（`raw <-> undistorted <-> table`），免除高开销整图插值。
   * `undistorted <-> table` 支持球台四点透视单应矩阵（`calibrate_table.py` 标定），并可回退线性 ROI。
   * 空间有限微元差分速度映射。
5. **卡尔曼状态估计层 (KalmanFilter)**：
   * 常量速度模型（`[px, py, vx, vy]`）融合位置观测序列，输出平滑 `CurlingState`。
   * 检测帧观测校正、检测间隔帧模型外推、丢轨时 reset；显著降低视觉抖动。
6. **统一物理、预测、规划与控制闭环**：
   * 物理轨迹预测核心统一并收敛至 `TrajectoryPredictor`，输出 `PredictionState`。
   * `TrajectoryPlanner` -> `ControlCommand` -> `PlcControlAdapter` -> `PlcOutputWorker`（非阻塞）-> `PLCInterface`。
   * 坐标范围检查、输出限幅（场内边界 / 速度上限 / 可选单步跳变限制）与时间戳字段。
   * Tkinter 零压缩 PPM 高速渲染管道与无头测试模式。
7. **仿真 / 评估 / 记录工具链**：
   * `simulation/`：无摄像头运动仿真（真实轨迹 -> 观测 -> Kalman -> 预测 -> 误差）。
   * `evaluation/`：多组实验误差评估与 JSON / 控制台报告。
   * `recording/`：真实/仿真统一格式运行日志（CurlingState / PredictionState / AIDecision / PLC request）。
8. **自动化单元测试集**：
   * 根目录 `tests/` 包含 143 个单元测试，覆盖 AI 决策、状态映射、卡尔曼估计、几何畸变差分、物理模拟、规划控制、记录格式、仿真评估、渲染与追踪器逻辑，无需依赖三方测试框架即可一键运行。

### 7.2 当前未完成内容

## 9. 真机运行与调试注意事项

1. **Jetson 功耗模式与性能锁频**：
   * Jetson Xavier NX 初始状态可能处于 `MODE_20W_2CORE`（仅开启 2 个 CPU 核心）。
   * 必须通过 root 权限切换至全部 6 核心模式并锁频：
     ```bash
     sudo nvpmodel -m 8     # 切换至 20W_6CORE 模式（需核对 nvpmodel -q --verbose）
     sudo bash air_hockey/tools/pre_test.sh # 执行手动锁频脚本，确保 CPU/GPU/EMC 调度器全切至 performance
     ```
   * **EMC（内存控制器）频率对高帧率图像从 DMA/硬件解码缓冲区拷贝至 CPU 内存带宽至关重要**，必须锁在最高频。

2. **高帧率相机与解码带宽**：
   * 摄像头标称 200 FPS 时，原生 GStreamer 管道为：
     `MJPG -> nvv4l2decoder -> nvvidconv -> BGRx -> appsink -> CPU BGR`
   * BGR 转换与 NumPy 拷贝仍占用一定 CPU。生产环境中建议加入 `--preview-fps 20` 限制 GUI 刷新，或直接运行 `--headless`。

3. **光照与冰面反光应对**：
   * 气浮台桌面反光和室内光源色温会显著改变 HSV 色域分布。
   * 在实机开机前，必须使用工具重新标定冰壶颜色阈值：
     ```bash
     # 采集单张实况照片并调整阈值
     python3 air_hockey/tools/test_image.py <frame.jpg> --output /tmp/result.jpg --lower 170 100 80 --upper 179 255 255
     ```

4. **无显示器 (Headless) 运行**：
   * 通过 SSH 登录 Jetson 调试时，若未挂载 X11 会话，请勿执行带 GUI 的命令，直接添加 `--headless`：
     ```bash
     python3 main.py --headless
     ```

## 11. 当前技术债务清单

为便于后续版本规划，当前存在的明确技术债务梳理如下：

### 11.1 实机物理参数未经系统辨识标定
* **现状**：[air_hockey/core_config.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/core_config.py) 中的摩擦系数、边墙弹性系数与球槌打击响应曲线基于虚拟游戏手感设定，未经真实台面数据拟合。
* **解法**：在真实冰台上释放不同初速度的冰壶，利用视觉系统记录实际运动衰减与碰撞反射点，通过最小二乘法回归出真实台面的物理参数；可复用 `air_hockey/evaluation` 做误差评估。

### 11.2 追踪状态机未细化（多目标支持缺失）
* **现状**：[tracker.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/air_hockey/vision/tracker.py) 仅有 `ACTIVE` / `LOST` 两种状态，且按单冰壶设计。速度平滑现由 `KalmanFilter` 承担，但追踪器本身仍缺少暂态/确认/遮挡预测等状态。
* **问题**：冰壶被球槌瞬间击打或短时穿过强反光区时，目标关联可能抖动或丢失；多冰壶场景无法区分。
* **解法**：细化状态机（TENTATIVE -> CONFIRMED -> OCCLUDED -> LOST），并引入多目标关联（匈牙利算法 / IOU 匹配）。

### 11.3 真机 AI -> PLC 运动闭环尚未实机联调
* **现状**：非阻塞输出链路（`TrajectoryPlanner` -> `PlcControlAdapter` -> `PlcOutputWorker` -> `PLCInterface`）已接入 [main.py](file:///run/media/shadowemperor/游戏/Ubuntu/Project/Python/Graduation/main.py)（`--plc`），但尚未与真实击球机构联调。
* **问题**：缺少端到端时延（相机曝光 -> 算法 -> PLC -> 电机）测量与前瞻补偿；PLC DB 无时间戳字段，坐标/速度单位与实机机构的映射仍待标定。
* **解法**：接入真实机构并做时延标定；如需，扩展 DB 布局增加时间戳与心跳字节。

### 11.4 缺乏自动化持续集成（CI）
* **现状**：项目当前仅通过本地 `python3 tests/run_tests.py` 执行测试，未搭建远端 CI。
* **解法**：添加 `.github/workflows/ci.yml`，在推流或提 PR 时自动执行 `compileall` 与轻量化单元测试。

### 11.5 标定与部署流程缺乏向导化封装
* **现状**：相机内参标定（`calibrate_camera.py`）、球台四点 Homography 标定（`calibrate_table.py`）、颜色阈值设置是割裂的独立脚本。
* **解法**：开发面向现场调试的一键式向导工具，串联棋盘格内参标定、台面四角点点击标定和冰壶色域自适应提取，并封装 Jetson 开机自启服务。
